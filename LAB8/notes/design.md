# З08. Ключ сортировки и партиция

## ORDER BY

В основной таблице `olap_product.fact_sales` используется `ORDER BY sale_id`.
Это не ограничение уникальности как в OLTP: `ORDER BY` задаёт порядок хранения
и первичный индекс ClickHouse. Идентификатор продажи не Nullable и подходит для
стабильного порядка строк.

В аналитических запросах фильтры по периоду выполняются через `dim_date`, а
магазин, товар и способ оплаты используются для группировки. Для небольшой
учебной витрины текущего ключа достаточно: он не вводит ложную уникальность и
сохраняет простой полный refresh из LAB7.

## PARTITION BY

Для проверки добавлена отдельная таблица
`olap_product.fact_sales_partitioned` с:

```sql
PARTITION BY intDiv(date_id, 100)
```

`date_id` имеет формат `YYYYMMDD`, поэтому деление на 100 даёт месяц `YYYYMM`.
Одна партиция соответствует одному месяцу. Это удобно для типичных отчётов
магазина: январь, квартал, сравнение месяцев и удаление старого периода.

Партиционирование сделано только в тестовой копии, а не изменением основной
таблицы LAB7. Так сохраняется воспроизводимость загрузки и отдельно виден
эффект `PARTITION BY` без смешения его с `ORDER BY`.

`ORDER BY` и `PARTITION BY` решают разные задачи: первый упорядочивает строки
внутри куска хранения, второй делит таблицу на куски по месяцам.
