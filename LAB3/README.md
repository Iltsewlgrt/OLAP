# З03. Таблицы в DuckDB

Лабораторная работа создаёт витрину продуктовой розничной сети города Гродно в DuckDB и загружает
исходные CSV из `data/raw/`.

## Структура

```text
LAB3/
├── data/raw/              # 13 CSV-файлов
├── sql/ddl_duckdb.sql     # DDL: 7 измерений и 6 фактов
├── convert_grocery_data.py# подготовка продуктового сырья
├── load_data.py           # создание и загрузка таблиц
├── checks.sql             # проверочные запросы
├── run_checks.py          # сохранение результата проверок
├── checks.txt             # последний вывод проверок
└── warehouse.duckdb       # создаётся при загрузке
```

## Гранулярность

| Таблица | Одна строка = |
|---|---|
| `dim_store` | один магазин сети |
| `dim_warehouse` | один склад или логистический центр |
| `dim_supplier` | один поставщик / производитель / импортёр |
| `dim_product` | одна товарная позиция каталога |
| `dim_customer` | один клиент |
| `dim_employee` | один сотрудник магазина |
| `dim_date` | один календарный день |
| `fact_visits` | одно посещение магазина клиентом |
| `fact_interest` | один факт интереса клиента к товару в рамках посещения |
| `fact_sales` | одна позиция продажи |
| `fact_loyalty` | одна операция по бонусам клиента |
| `fact_logistics` | одна поставка товара |
| `fact_inventory` | один остаток товара на дату |

Главная мера — `fact_sales.total_amount`, деньги хранятся в `DECIMAL(14,2)`.
Продажи выражены в BYN; средняя сумма строки продажи находится в диапазоне,
характерном для продуктовой розницы, а не для ювелирных изделий.

## Подготовка продуктовых данных и запуск

Нужен Python 3.13+ и пакет DuckDB:

```powershell
py -3.13 -m pip install duckdb
py -3.13 convert_grocery_data.py
py -3.13 load_data.py
py -3.13 run_checks.py
Get-Content checks.txt
```

`convert_grocery_data.py` выполняется один раз после получения исходных CSV:
заменяет ювелирный пример на продуктовый ассортимент, продуктовые магазины,
поставщиков и цены в BYN. Все торговые точки, склады, сотрудники и клиенты
относятся к Гродно. Повторный запуск этого скрипта поверх уже
преобразованных файлов не нужен; для чистого повторения сначала скачайте
исходные CSV заново.

`load_data.py` сначала создаёт таблицы, затем удаляет старые строки в порядке
от фактов к измерениям и загружает CSV. Поэтому повторный запуск не удваивает
данные. При отсутствии любого обязательного CSV загрузка завершается с ошибкой, поэтому
неполная витрина не будет ошибочно принята за успешно загруженную. Итоговые
количества строк печатаются в консоль.

## Проверки

`checks.sql` проверяет количество строк во всех таблицах, пустые ключи
`fact_sales`, количество и сумму продаж, себестоимость и прибыль, средний чек,
способы оплаты, диапазон дат и пять магазинов с максимальной выручкой.
Результат каждого запуска `run_checks.py` полностью заменяет `checks.txt`.
